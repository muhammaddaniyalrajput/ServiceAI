## Overview

ServiceFlow AI is an **Agentic AI Service Booking Platform**. A user types a natural language request
(English, Urdu, or Roman Urdu), and a chain of 6 AI agents automatically extracts intent, finds
providers, ranks them intelligently, simulates a booking, sends a localized notification, and schedules a follow-up.

---

## 1. What the System CAN Do RIGHT NOW ✅

### 1.1 Backend — Fully Functional

#### Agent Pipeline (All 6 Agents Working)

| # | Agent | What It Does Right Now | Status |
|---|-------|------------------------|--------|
| 1 | **Intent Agent** | Calls Gemini 2.0 Flash with a system prompt, parses EN/Urdu/Roman Urdu text into structured JSON (`service_type`, `location`, `datetime_hint`, `urgency`, `language`, `confidence`). Has 3-retry logic via `tenacity`. | ✅ Working |
| 2 | **Provider Discovery Agent** | Filters 14 mock providers by matching service category. Calculates real Haversine distance in km from user's sector (G-13, F-8, I-10, etc.) using hardcoded Islamabad coordinates. | ✅ Working |
| 3 | **Ranking Agent** | Scores every matching provider 0–100 using weighted algorithm (rating 35%, distance 30%, price 20%, experience 10%, verified 5%). Then calls Gemini to write a human-readable "why this provider" reasoning paragraph. | ✅ Working |
| 4 | **Booking Agent** | Generates a unique `SFW-XXXXXX` confirmation code. Resolves Urdu time hints (`kal subah` → tomorrow 9am, `aaj sham` → today 5pm). Calculates ETA based on urgency. Estimates total cost (hourly rate × 2hrs). | ✅ Working |
| 5 | **Notification Agent** | Builds an FCM-ready push notification payload. Localizes the message in **English, Urdu (Nastaliq script), or Roman Urdu** based on detected language. | ✅ Working |
| 6 | **Follow-Up Agent** | Schedules a satisfaction survey reminder. Awards 50 loyalty points. Returns structured survey fields for the mobile app to render. | ✅ Working |

#### API Endpoints

| Method | Endpoint | What It Returns Right Now |
|--------|----------|--------------------------|
| `POST` | `/api/v1/analyze-request` | `booking_id` + structured `intent` + Intent Agent logs |
| `POST` | `/api/v1/find-providers` | Raw provider list + ranked list (scored best→worst) + Discovery/Ranking logs |
| `POST` | `/api/v1/book-service` | Full booking result + FCM notification payload + follow-up payload + all agent logs |
| `GET`  | `/api/v1/booking-status/{id}` | Current status of any booking by ID |
| `GET`  | `/api/v1/agent-logs/{id}` | Full reasoning trace of all agents for a booking |
| `GET`  | `/health` | `{"status":"ok"}` |
| `GET`  | `/docs` | Interactive Swagger UI for all above routes |

## 3. Current Data Flow (What Actually Executes)

```
[User hits POST /analyze-request]
         │
         ▼
  Orchestrator creates booking_id (UUID)
  Saves booking doc to mock store / Firestore
         │
         ▼
  Intent Agent → Gemini API call
  Returns: service_type, location, datetime_hint, urgency, language, confidence
  Logs saved to mock store / Firestore
         │
         ▼
  Returns booking_id + intent + logs to caller
  
[User hits POST /find-providers with booking_id + intent]
         │
         ▼
  Discovery Agent → filters 14 mock providers by service name
  Calculates Haversine distance for each
         │
         ▼
  Ranking Agent → scores all matched providers 0–100
  Calls Gemini for human reasoning on top pick
  Logs saved
         │
         ▼
  Returns: providers[], ranked[] (sorted best→worst) + logs

[User hits POST /book-service with booking_id + provider_id + intent]
         │
         ▼
  Booking Agent → generates SFW-XXXXXX code, calculates ETA + cost
         │
         ▼
  Notification Agent → localizes FCM payload (EN/UR/Roman UR)
         │
         ▼
  Follow-Up Agent → creates survey + loyalty reward payload
  All logs saved
         │
         ▼
  Returns: booking{}, notification{}, follow_up{}, logs[]
```
